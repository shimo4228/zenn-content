# ADR-0015: Zenn 稿の構造凍結前に、記事ごとのペルソナ読みで見せ方を改稿するループを置く

## Status

Accepted

## Date

2026-10-09

本 ADR は [ADR-0011](./0011-dismantle-the-eval-layer.md) Decision 3 のうち「改稿ループを削除する」部分を部分 supersede する。
ADR-0011 Decision 2（完成稿の受け入れは panel と著者の通読）はそのまま立つ。ADR-0011 の該当節に日付つき注記を置く。
[ADR-0001](./0001-content-integrity-principle.md)（Content 層は最適化のために変えない）と
[ADR-0005](./0005-post-publication-eval-loop.md)（予測型エンゲージメントレビュアーの不採用）との両立は Decision 10 に書く。

## Context

Plan: [docs/plans/article-persona-loop.html](../plans/article-persona-loop.html)（承認 2026-10-09）

著者の提案（2026-10-09）: 「ZennのEvalの仕組みだけど、Readme judgeみたいに記事ごとのジャッジのペルソナを設定してループ回す形にしたらどう？」。
選択肢（タイトルだけ / タイトル＋本文の初見の読みを 1 回 / 本文もループ）から、著者は本文もループする案を選んだ。止めどきは
「私が日本のハーネス構築において並ぶ者がいないほど考えていることがわかるレベルまでにして」。

先例は global harness の readme-writer にある訪問者役の読み。repo ごとに 3 人を選び、著者の設定を読まない `claude -p` で r0, r1… と
読ませ、試すかどうかと理由で止める。readme-writer の maintenance notes によれば、訪問者役は判定器と別の失敗（料金が分からない・造語）
を拾った。一方 2026-10-09 には、読み手のモデルがカットオフ後の Claude Code の mods を知らず「Mod が分からない」と言った偽陽性に
従って入口の語を外し、著者の通読がそれを誤りと見つけた（readme-writer の read-through-log）。

ADR-0011 が改稿ループを外した理由は二つ: judge を通った稿に著者の通読と別モデルが欠陥を見つけ、judge が受け入れゲートとして
機能していなかったこと。修正を reviewer に読み直させると指摘が尽きず、本文が防御的になったこと（writing-ecosystem の処分規律）。

調査（[docs/plans/research/2026-10-09-article-persona-loop.md](../plans/research/2026-10-09-article-persona-loop.md)、as-of 2026-10-09）:

- LLM の判定は、研究アイデアの質の判別で人間 reviewer 同士の一致を下回った（Si et al. arXiv:2409.04109 §7.2）。研究課題の新規性の判定は
  人間の専門家と食い違い、過大評価の方向だった（arXiv:2606.12071）。後者では、参照と生成物を並べて採点した設定でモデル側の勝ちが増えた
  （report の読み。論文自身は absolute / pairwise の語を使っていない）
- 同一モデルの改稿と judge の反復では、改稿履歴を共有する judge の点が高止まりし、人間の点は最終反復で下がった。1 本ずつ独立に読む
  judge は GPT-3.5 で人間に近かった。GPT-4 では点が高いままだった（Pan et al. arXiv:2407.04549）
- 批判に応じた改稿は限定句を増やした（初稿で差なし、改稿後に 1,000 語あたり +1.95）。改稿 1 回ごとに Clarity が下がった（LLM judge の
  5 点尺度で -0.14）（arXiv:2609.14767）
- 改稿で台帳に無い数値・最上級が足され hedge が外れる変化を、機械 diff で数える drift 指標がある（arXiv:2608.28596、preliminary。
  改稿の指示文は未確認）
- 隔離した読み手（書き手の文脈を渡さない・検索させない・毎回新しい agent）は Dify docs の reader-test、first-reader、readme-writer の
  3 件で一致した。他の記事を比較材料として読み手に渡す実装は見つからなかった
- Claude 5 世代と日本語の記事での測定は見つからなかった

隔離の実測（2026-10-09、Claude Code 2.1.295）: `claude -p --setting-sources "" --strict-mcp-config --tools "" --model sonnet` を repo の
中と外で起動し、「執筆の背骨」など著者の rules の見出しが見えるかを聞くと、どちらも NONE だった。`--setting-sources` を外すと 3 つの
見出しを引用した。`--bare` は CLAUDE.md の読み込みも止めるが、認証が API キーに限られサブスクで使えない（`claude --help`）。

## Decision

1. **Zenn 稿の brief 承認後・構造凍結前に、ペルソナ読みを置く。** 手順の正本は
   `.claude/skills/writing-ecosystem/references/persona-read.md`。writing-ecosystem の §3.5 と brief の `Personas:` 行から指す
2. **読み手は記事ごとに 3 人（`primary` / `inflow` / `practitioner`）。`practitioner` は毎回「日本のハーネス実践者」にする。** 人選は
   brief で著者が確かめ、ラウンド間で固定する

   > **注記（2026-10-09, commit「docs(writing): ペルソナの人選を著者の確認なしにする」）**: 人選は orchestrator が brief に書き、
   > 著者の確認を待たない（著者「ペルソナ別に確かめなくていいよ」）。ラウンド間で固定することはそのまま立つ。

3. **読み手は上の隔離した `claude -p` で、毎ラウンド新しいプロセスで読む。** brief・中心命題・台帳は渡さない。記事ごとに、著者の rules
   の見出しが読み手に見えないことと、隔離を外すと見えることを確かめる
4. **止めどきは、読後に残った著者の判断の言い直しと brief の判断の照合（一致 / ずれ / 欠落）で決める。** 深さの印象は記録だけにする。
   読み手の「分からない語」は著者へ渡し、説明の 1 文を足すかは著者の通読が決める
5. **比較材料（Zenn API で検索時点に取った記事 2〜3 本）は、止めたラウンドで 1 回、`practitioner` にだけ渡す。** 1 本ごとに左右を
   入れ替えて 2 回読ませ、両順で同じ側を選んだときだけ記録する。止めどきに使わない
6. **改稿は見せ方だけを直す。** 事実の不足は著者へ渡す。改稿したラウンドごとに、全文の差を `scripts/drift_count.py`（test:
   `scripts/tests/test_drift_count.py`）で数える。台帳に無い数値・最上級の追加・限定句の増減・台帳に無い英字の固有名のどれかが出たら、
   著者の確認なしに次のラウンドへ渡さない。カタカナの新語は exit に効かない一覧として目で読む
7. **改稿は 3 周で打ち切る。** 判断の言い直しが 3 人とも一致し新しい理由が出ないか、残りが著者へ渡すものだけなら、それより前に止める。
   3 は readme-writer の運用に合わせた値で、較正していない
8. **受け入れは変えない。** panel（channel reviewer・fact-checker・Codex の初見の読み）は凍結稿に各 1 回。読み手の評価は受け入れ条件に
   せず、`publishing-channels.md` の Shared acceptance profile には記録の有無と止めた理由だけを置く
9. **著者の内容 GO の時点で、通読の指摘数を** `.claude/skills/writing-ecosystem/evals/read-through-log.md` に記事ごと 1 行で記録する。
   比較の基準は、ペルソナ読みを使う前で panel が同じ構成（ADR-0013 以降）の直近 3 本 — `jev-guard-blind-to-local-verify`・
   `harness-scope-writing-harness`・`readme-human-llm-fold` — の通読指摘数で、各稿の処分記録（非公開の drafts）と commit 本文から拾って
   最初に書く
10. **ADR-0001・ADR-0005 とは、改稿の目的で区別する。** ADR-0001 Notes は、構成への提案が Content 改変か品質レビューかを「誰のために
    変えるか — 読者のエンゲージメントのためか、著者の論旨をより正確に伝えるためか」で分ける。ペルソナ読みが直すのは、読み手が著者の
    判断を言い直せなかった箇所の見せ方で、後者に当たる。読み手が止まった箇所（`stopped_reading_at`・`pushed_away`）は判断の照合と
    一緒に読む材料で、読み続けさせること自体を改稿の目標にしない（ADR-0005 が退けたフォロー意向の最適化にしない）

ADR-0011 の理由 2（読み直しで指摘が尽きず本文が防御的になる）には、Decision 6 の限定句の増減の計数と Decision 7 の上限が答える。

## Review-when

判定者は著者。記録は `.claude/skills/writing-ecosystem/evals/read-through-log.md` と、その稿の commit 本文に置く（`drafts/` は非公開で消えうる）。

- ペルソナ読みを回した Zenn 稿 3 本で、著者の通読の指摘数が基準の 3 本（Decision 9）と比べて減らない — 段ごと外すかを著者が決める。
  3 本対 3 本で 1 本あたりの指摘は数件なので、この比較は検定でなく著者の判断の材料にする。比べる間は panel の構成と回数を変えない。
  同じ窓は ADR-0013 の Review-when（Codex の初見の読みが著者の通読の指摘を先取りできるか）と重なり、凍結前に直した稿を Codex が
  読むので、両方の測定は交絡する
- 著者の通読が、ペルソナ読みで直した箇所を元に戻すことが 2 本続く（見せ方の改稿が著者の判断から離れた）
- `drift_count.py` が 1 本の稿で毎ラウンド発火する状態が 2 本続く — 発火した語を読み、主張の水増しか検出の誤り（言い換えた英字の語など）
  かを分けてから、改稿範囲の書き方か検出の語彙のどちらかを直す
- Claude 5 世代以降の判定器で、新規性・専門性の判定が人間の専門家と一致するという測定が出る — Decision 4・5 の「記録だけ」を見直す
- Claude Code の版が上がり、Decision 3 の確かめで著者の rules の見出しが読み手に見える — 隔離の起動形を直すまでペルソナ読みを止める
- 著者の通読を省く運用に変わる — 本 ADR の前提（読み手は材料、受け入れは通読）が消える

## Alternatives Considered

- **タイトルだけを記事ごとのペルソナで eval する** — 著者が選ばなかった。題の語は ADR-0001 の Distribution 層で、受信の代理指標で
  変えてよい範囲に入る。著者の目標は本文で考えの深さが伝わることにあり、題だけでは届かない
- **本文の初見の読みをペルソナ化して 1 回だけ読ませる（ループなし）** — 著者が選ばなかった。処分規律を変えずに済むが、読み手の言い直しの
  ずれを直したかを確かめる手段が著者の通読だけになる
- **読み手を Codex（別系統のモデル）にする** — Open — revisit when: ペルソナ読みを回した稿 3 本で、読み手の判断の言い直しが一致したのに
  Codex の初見の読みか著者の通読が同じ判断の読み違いを見つけたとき。今は採らない理由: ADR-0013 が Codex に初見の読みを置いたのは凍結稿を
  別系統で 1 回読むためで、同じ Codex を凍結前の改稿ループにも使うと、凍結稿を読む Codex が自分の指摘で直された稿を読むことになる。
  Claude の sonnet は書き手（orchestrator）と別のモデルだが同系統で、自己選好は残る（Consequences）
- **「並ぶ者がいないか」を読み手に直接聞いて止めどきにする** — 不採用。新規性の判定は過大評価の方向に偏った（2606.12071）。読み手の yes で
  止めると、改稿役が権威の語や固有名を足して登る経路が開く
- **比較材料との対比較を止めどきにする** — 不採用。参照と並べた採点でモデル側の勝ちが増えたという読みがある（2606.12071、report の読み）
- **比較材料を渡さない** — 不採用。比較を渡す実装は見つからなかったが、著者の目標の相対部分（並ぶ者がいない）を見る材料が通読以外に無くなる。
  記録だけなら止めどきを歪めない
- **ループを構造凍結の後（panel の後）に置く** — 不採用。凍結稿への panel 各 1 回の規律が崩れ、ADR-0011 が外した reviewer の読み直しに戻る
- **周回の上限を 2 にする** — Open — revisit when: 基準の比較（Review-when 1）で、3 周目に入った稿の通読指摘が 2 周で止めた稿より多いとき。
  改稿ごとに Clarity が下がる・最終反復で人間の点が落ちるという調査結果は 2 も 3 も同じように支え、3 を選んだのは readme-writer の運用に
  合わせたからで、2 を退ける証拠は無い
- **周回の上限を 5 にする** — 不採用。上の 2 つの調査結果が、周回を増やす向きに逆らう
- **ループの外の照合に人間の読み手 1〜2 人、または公開後の実測（`scripts/metrics/snapshots.jsonl`）を足す** — 著者が plan で選ばなかった。
  人間の読み手は記事ごとに依頼の手間が出る。公開後の実測は ADR-0005 の事後ループが既に持ち、内容ランクと実測の乖離を見る役は
  article-stocktake にある

## Consequences

- 良: 著者の判断（決めたこと・決めなかったこと）が読み手に残ったかを、凍結前に読み手の語で確かめられる。panel と fact-checker は確定した
  構造に 1 回だけ当たる
- 良: 主張の水増しと確度の上げ下げを、LLM の判定でなく機械の diff で検出する。確度の上限（背骨 1）を改稿ループの中でも機械が支える
- 良: 手順は `persona-read.md` に置き、受け入れ側の記述は `publishing-channels.md` の 1 行だけにする
- 悪: 止めどきの照合（一致 / ずれ / 欠落）をするのは改稿役の orchestrator 自身で、brief を全部持ち、止めたい動機もある。Pan が乖離の原因に
  挙げた書き手と判定者の文脈の共有は、読み手を隔離しても照合の段に残る。照合の 3 値は読み手の文の引用と並べて記録し、著者の通読が見る
- 悪: 読み手は Claude（sonnet）で、書き手も Claude。自己選好は残り、判断の言い直しが一致しても妥当性の証拠にはならない
- 悪: 改稿役が文を書くので、著者の言い回しが Claude の既定の文体へ寄りうる（report の均質化の項）。drift の計数はこれを数えない
- 悪: 比較の記録は、本文を AI が書いた稿を、参照と並べると上振れしうる形式で比べた結果になる。記録だけにしても、自稿側に偏った数字が
  著者に届く
- 悪: Zenn 稿 1 本ごとに、読み手 3 人 × 最大 4 回（r0〜r3）と止めたラウンドの比較 4〜6 回（2〜3 本 × 両順）の `claude -p` が増える。
  著者の手間も増える — 人選の確認、drift が出るたびの確認（言い換えた英字の語でも発火する）、事実の不足と分からない語の引き取り
- 悪: drift の語彙リスト（最上級・限定句）は手書きで、言い換えた水増しは数えられない。漢字の固有名は落ちる
- 戻すコスト: `persona-read.md`・`.claude/skills/writing-ecosystem/MAINTENANCE.md` の該当節・`scripts/drift_count.py`・
  `scripts/tests/test_drift_count.py` を消し、writing-ecosystem の §3.5・brief の `Personas:` 行・Ecosystem Map の行、
  `publishing-channels.md` の 1 行、`docs/CODEMAPS/scripts.md` の節、ADR-0011 の注記、`docs/adr/README.md` の行を戻す。
  `.claude/skills/writing-ecosystem/evals/read-through-log.md` は段を外しても通読指摘数の記録先として残す
