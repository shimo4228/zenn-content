# ADR-0006: 著者の判断・価値観の 2 スキル正本化（zenn-authorial-values / zenn-editorial-judgment）

## Status

Accepted

## Date

2026-07-28

## Context

2026-07-04〜07-28 の 33 執筆セッション（人間発話 314 turn）を全量発掘した結果、著者が記事作成で繰り返し下している判断・価値観のうち、相当部分がスキル化されずに memory の `feedback_*` 8 ファイルと会話履歴にのみ存在していた。具体的には:

- 記事タイプの事前判定（how-to か立場表明か）と「わかること行・壁の箇条書き」等の装置の採否
- 軸ずれ検出（自分の環境の出来事は素材であって軸でない）
- レビューエージェント通過後の構造自己審問（3 レビュワーが拾えない骨格の歪み）
- 主張型記事の業界 Deep Research 裏取り
- 具体性の取捨（実名許可 ≠ 全ディテールを出す義務）
- 著者ペルソナ規約・内容ランク A/B/C 基準

さらに全量発掘で memory 未記録の判断も発見された（分割より統合 / 書いた後でも公開を取りやめる / 著者の事実の捏造検知 / 記事とハーネスの整合 / 通読ゲート / 実測値以外の数値不信 / 訳語ライフサイクル）。

memory の feedback は auto-memory の確率的リコールに依存し、執筆・改稿の実作業時に確実に効かない。既存スキル（`zenn-practical-writing` 等）は「どう書くか」の正本であり、「いつ・何を判断するか」「なぜそう判断するか」の層が空白だった。

## Decision

1. **2 スキルに分割して正本化する**:
   - `zenn-authorial-values` — 価値観リファレンス。「著者が何を大事にしているか」（why）を実セッション引用付きで保持。著者ペルソナ規約・内容ランク A/B/C 基準の正本もここに置く
   - `zenn-editorial-judgment` — 判断ゲート集。執筆タイムラインに沿った「いつ・何を判断するか」（when/what）。タイプ判定 → 軸ずれ検出 → 執筆中判断 → 構造自己審問 → 裏取り作法
   - 分割理由: 発火文脈が異なる（values は方針議論・企画・ハーネス設計時、judgment は執筆・改稿の実作業時）。1 本にすると description が両義的になり確率的トリガーの精度が落ちる
   - 相互参照: judgment の各ゲートは why を values へポインタ、values は運用を judgment へポインタ。価値観の本文は values のみが持つ（再掲しない）
2. **feedback memory は削除せず一次資料として残置する**。originSessionId と生の事例を持つ監査資料であり、各ファイル先頭に昇格マーク 1 行のみ付す。スキルは蒸留された規則、memory は生事例、という役割分担
3. **quality-gate には統合しない**。判断層を機械 gate 化すると「チェックリストを埋めるために部品を足す」テンプレート化の弊害が起きる（`feedback_reader-problem-not-author-framing` 自身が警告する失敗パターン）。zenn-editorial-judgment は著者判断の再現装置であり、機械検査の追加ではない
4. **zenn-practical-writing にタイプ別免除条項を追加する**。同スキルの受け入れチェックリストは「冒頭にわかること行」等の装置を無条件必須としており、立場表明記事へのフレーム過剰適用（small-llm-by-choice #0 で実証済みの失敗）と形式矛盾する。Phase 1 の前にタイプ判定を挟み、立場表明では装置を免除して声だけ適用する

## Alternatives Considered

- **1 スキルに統合（価値観テーブル + 判断ゲートの二層構成）**: 当初案。発火文脈の違いで description が両義化する問題と、ユーザーの明示指定（「両方を別スキルでそれぞれ作って欲しい」）により棄却
- **既存スキルへの追記のみ（新規スキルなし）**: Knowledge Placement 原則の第一候補だが、zenn-practical-writing は「書き方」の正本で 229 行あり、判断層 8+ 領域を足すと責務が混濁して肥大する。ADR-0002 §3（責務は 1 コンポーネントに 1 つ）に反するため棄却
- **memory の feedback を正本に昇格（スキル化しない）**: auto-memory は確率的リコールで実作業時の発火が保証されず、user-invocable にもできないため棄却
- **quality-gate への統合**: 上記 Decision 3 の理由で棄却

## Consequences

- 執筆・改稿セッションで著者の判断が明示的に参照可能になる（`/zenn-editorial-judgment` で明示呼び出しも可）
- 同じ指摘の再発時、会話でなくスキルへの追記で受け止められる（価値観 7 項の「指摘はハーネスへ昇格」の実装）
- zenn-practical-writing のチェックリストは「タイプ判定を通過した how-to」に対してのみ全項目適用となり、立場表明記事で装置が免除される
- memory `article-quality.md` の A/B/C 判定基準は zenn-authorial-values への参照となる（判定台帳の機能・article-stocktake / ideation の読み先は不変）
- スキルが 2 本増える分、次回 skill-stocktake の審査対象が増える。両者の境界が崩れたら（片方がもう片方を再掲し始めたら）統合を再検討する
