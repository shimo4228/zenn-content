# ADR-0008: 二本立て評価関数（テーマ / 記事品質）と改稿ループの導入

## Status

Accepted

## Date

2026-08-12

## Context

2026-08-12 のエッセイ制作セッションで、essay-reviewer GOOD・zenn-clarity-reviewer PASS・fact-checker 全項目 ACCURATE を通過した原稿に対し、著者自身が重大な瑕疵を 3 件発見した（古い論拠への依存・改稿の継ぎ足しによる論理の不明瞭・非論理的な文）。既存レビュー chain の合格と著者基準の間にギャップがある。同じセッションの再レビューは、意図的な短文リズムを「ですます調の破れ 14 件」と数えるノイズも出しており、厳しさの不足とノイズの過剰が同時に存在していた。

また著者の編集判断として「そもそものテーマが弱いと、記事をどれだけ磨いても全体の評価は上がらない」が明確化した。execution の改稿だけを厳しくしても、テーマの上限は超えられない。

外部調査（as-of 2026-08-12、証拠台帳: `drafts/` 同日付ファイルおよび grill-me セッション記録）は次を示した: 二値チェックリスト分解は Likert 直接採点を評価者間一致で上回る（CheckEval / TICK / BinEval）。LLM judge の甘さは指示では直らず、決定論検出の外付けで塞ぐのが実務の共通解（EQ-Bench）。自己批評は self-preference と blind spot（64.5%）で構造的に破綻し、fresh-context の別プロセス判定が優る（CCR 2026-03）。反復改稿は 2〜3 回で頭打ちし、以降は voice の正規化ドリフトが「voice を保て」プロンプトでも防げない形で進行する（Voice Under Revision 2026-04）。

## Decision

1. **評価をテーマ層と execution 層に分離する（二本立て）**。テーマ評価は `theme-eval` skill が執筆前と完成稿の 2 時点で行い〔※ 2026-08-23 追記: 完成稿での再判定は著者判断で廃止。公開可否に効かず memory への記録だけのステップだった。現行は執筆前の 1 時点（ADR-0010）〕、テーマランクを記事品質の上限（ceiling）として扱う。verdict は `Write-A見込み / Write-B見込み / Deepen` の 3 値で、**却下ゲートにしない** — Deepen（深化プロンプト付き）は 2 回まで、上がらなければ見込みランク付きのまま記事化してよい。Drop を選べるのは著者のみ。
2. **execution 層は「決定論の機械層 + fresh-context の LLM 層」の二段で判定する**。機械層は `scripts/mechanical_checks.py`（slop 語・決め構文・段落密度・voice 回帰等の証拠 JSON、判定はしない）。LLM 層は `article-judge` agent（動的二値チェック + 固定コア質問 + 反証プレッシャーテスト、集計しない named verdict `Publishable / Fix / Rewrite`）。判定形式は global `llm-as-judge` skill に準拠する。
3. **品質バーの基準アンカーは Kaguura 記事から蒸留した完全版 craft チェックリスト**（`.claude/refs/kaguura-craft-checklist.md`、全文アーカイブは `.notes/refs/`）とする。**著者の過去記事は厳しさの基準に使わない**（著者明言）。

   > **2026-08-23 注記**: 用語を整理した。チェックリストは article-judge の**質問セット**で、規約の正本は `writing-ecosystem` / `theme-eval` / `title-eval`、閾値・語リストの正本は `scripts/mechanical_checks.py`。本決定の実質（判定に固定の質問セットを使う・著者の過去記事を基準にしない）は変えていない。
4. **改稿ループを `writing-team` に配線する**。Fix → span 単位修正 → 同一チェックセットで再判定 1 回、上限 2 ラウンド、voice_delta 警告で磨きを止める。人間ゲートは judge 間不一致（article-judge vs codex-review）と publish 直前の通読 GO の 2 箇所のみ。**著者の関与はテーマ層（Deepen の問い）に集中させる**。

## Alternatives Considered

- **既存レビュアーの合格ラインを引き上げる（editor を EXCELLENT 必須にする等）**: 実装は最小だが、今日の見逃し（as-of 不整合・継ぎ接ぎ・文単位の非論理）は既存レビュアーの観点自体に含まれておらず、閾値操作では拾えない。不採用。
- **著者の過去指摘・過去記事を教師データにした著者基準 judge**: 著者自身が「過去記事は厳しさの参考にならない」と判断（2026-08-12）。著者指摘は運用での基準再起草（不一致記録）に限定して使う。主軸としては不採用。
- **rubric スコアリング（N 点満点の合格閾値）**: 中心化・希釈・説明不能の既知問題に加え、llm-as-judge skill が集計を明示的に禁じる。既存の `schedule-publish` の 4 軸 12 点スコアはこの原則に反する先行事例として記録するに留め、本 ADR のスコープ外とする（別途検討）。
- **改稿ループの反復回数を増やす（収束まで無制限）**: 反復は 2〜3 回で頭打ちし voice 劣化が始まるという外部実証、および「2〜3 回目が最良で 7〜10 回目は元に戻した」という実務報告に反する。不採用。
- **テーマ評価を却下ゲートにする**: 週 2〜3 本の公開ペースでは常に A テーマは湧かず、ゲート化は執筆停止を招く。「弱くても深めて、上がらなければ上限認識のまま書く」を著者が明示選択（2026-08-12）。不採用。

## Consequences

- 良: 「レビュー全通過 ≠ 著者基準」ギャップの主因 3 種（as-of 不整合・継ぎ接ぎ・文単位の非論理）が article-judge の固定コア質問 K1-K3 として常設化される。テーマの弱さが execution の磨きで隠れなくなる。
- 良: 人間の関与がテーマ層に集中し、execution は自動ループで回る（著者は執筆者ではなく問いを深める側、という分業の明文化）。
- 悪/コスト: 新規記事 1 本あたり判定コストが増える（theme-eval 2 回 + article-judge 1〜3 回 + 機械チェック）。ループ上限 2 ラウンドと「Notes = 判定は一晩寝かせない」で抑える。
- リスク: judge の好みへの文体収束（平坦化 Goodhart）。対策として評価は欠陥検出に限定し（ADR-0001 Content Integrity と同根）、voice 回帰テストを機械層に常設、cross-model（codex）を最終ラウンドに 1 回配置する。
- 検証義務: テーマ層は過去 58 本台帳（memory `article-quality.md`）との突合バックテスト、execution 層は 2026-08-12 エッセイ中間版での著者指摘再検出スモークテストを実装完了の定義とする。外部実証値は 2026-08 時点のモデル世代依存 — 主要モデルの世代交代時に上限回数・blind spot 前提を再検証する（knowledge-staleness）。
- 関係: ADR-0004（新レビュアー追加基準）の手続きに従う追加。ADR-0005（事後 Eval）とは時点で分担（本 ADR = 公開前、0005 = 公開後実測）。ADR-0006 の「editorial-judgment は機械 gate に組み込まない」は維持 — theme-eval / article-judge は著者判断の代行ではなく、判断材料の供給装置。ADR-0007（Kaguura 取り込み）を評価基準の正本として拡張。
