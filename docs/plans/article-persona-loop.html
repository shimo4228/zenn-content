Zenn 記事のペルソナ読みループ

Why · 著者の発言 3 つと調査 report ZennのEvalの仕組みだけど、Readme judgeみたいに記事ごとのジャッジのペルソナを設定してループ回す形にしたらどう？ 3 私が日本のハーネス構築において並ぶ者がいないほど考えていることがわかるレベルまでにして LLM の新規性判定は人間専門家と食い違い、過大評価の方向だった … 改稿で hedge が増える点は supported、「内容は劣化しない」は unsupported

記事ごとに読み手 3 人を brief で決める

3 人目は日本のハーネス実践者に固定する

新しい機能の語の「分からない」は追わない

読み手は凍結前の稿を隔離して読む

読み手は読後に残った判断を自分の語で返す

止めどきに使う読み手の答えはどれか
読み手の yes が止めどきになると、改稿役は権威の語・固有名を足す方向に登る（report の authority bias）。claim 3.1 の数え上げが唯一の歯止めになる。

比較材料との対比較は両順で読み、記録だけにする

比較材料を読み手に渡すか
この claim は消え、「並ぶ者がいない」の相対部分は著者の通読だけが持つ。

改稿は見せ方だけを直し、主張を足さない

足した数値・最上級・限定句を機械で数える

止める 1 件でも出たら、その改稿を著者の確認なしに次のラウンドへ渡さない。

ループは 3 周か新しい理由が消えたら止まる

改稿の周回の上限は何回か
Loop-Back（2609.14767）では改稿 1 回ごとに Clarity が下がった。Pan（2407.04549）では最終反復で人間の点が落ちた。

panel は凍結稿に 1 回のまま変えない

公開の可否は著者の通読が決める

ループの外で読み手を照合する手段はどれか

ADR-0015 が ADR-0011 の改稿ループ廃止を覆す

手順は references の 1 本に集める

実行者の決定: 誰が実装するか

変えないもの

  • 背骨（writing-principles.md）と、確度の上限が著者の言葉であること
  • panel 3 本（editor・fact-checker・Codex の初見の読み）とその回数
  • title-reviewer と headline-craft。タイトルの eval はこのプランの外
  • note・Substack・Dev.to の手順。ペルソナ読みは Zenn だけで始める
  • skill description の記事の brief。ループは凍結前に回るので、brief はこのプランと並行で進める
