# Ideation Skill

**Purpose:** 記事のテーマを検討し、著者の思考を引き出す。

---

## Usage

```
/ideation                        # 対話的にテーマを探る
/ideation "エージェントの記憶"    # 特定テーマの記事化を検討
```

---

## Process

### Step 1: 種を見つける

以下の情報源からテーマの種を収集する:

1. **最近の作業**: git log から直近の開発活動を確認
2. **未公開ドラフト**: `drafts/` や `published: false` の記事
3. **ユーザーの関心**: 対話で「最近何を考えているか」を聞く
4. **既存記事の隙間**: 公開済み記事を一覧し、カバーされていないテーマを探す

### Step 2: テーマの深掘り

種が見つかったら、以下を確認する:

- **コア論点**: このテーマで一番伝えたいことは何か（1文）
- **独自性**: 自分だけが書ける理由は何か（体験、実験、発見）
- **読者像**: 誰が読んで、何を持ち帰るか
- **記事タイプ**: tech（手順・実装）or idea（思想・設計哲学）

### Step 3: 記事化判断

以下の基準で記事にする価値があるか判断する:

| 基準 | 判定 |
|------|------|
| 著者自身の体験・実験に基づくか | 必須 |
| 1つのコア論点に絞れるか | 必須 |
| 独立した論点が4つ以下か | 必須（超えたら分割） |
| 既存記事と重複しないか | 確認 |

### Step 4: 提案

```markdown
## テーマ提案

**タイトル案**: [概念を伝えるタイトル]
**コア論点**: [1文]
**記事タイプ**: tech / idea
**独自性**: [自分だけが書ける理由]
**想定読者**: [誰が読むか]
**推定ボリューム**: [字数の目安]

### 次のステップ
- [ ] 素材を集める（コード、ログ、スクリーンショット）
- [ ] zenn-drafter で構成案を作る
```

---

## Notes

- テーマの強制はしない。著者が「書きたい」と思えることが最優先
- 検索流入やバズを理由にテーマを推薦しない（Content Integrity 原則）
- 複数のテーマ候補がある場合は、優劣をつけずに並列提示する
