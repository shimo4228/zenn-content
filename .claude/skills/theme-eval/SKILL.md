# theme-eval — テーマ（問い）の強度評価（執筆前）

> 判定形式の正本は `~/.claude/skills/llm-as-judge/SKILL.md`（二値チェック → 反証プレッシャーテスト → 集計しない named verdict）。
> 設計経緯: ADR-0008 + `.notes/theme-eval-backtest-2026-08-12.md`（レイヤー純化と アンカー撤去の 2026-08-12 改稿を含む）。

## 原則

1. **テーマ層は「問いの性質」だけを測る**。実測データの強度・物語の立ち方・文章の質は execution 層（article-judge / Kaguura craft）の指標であり、ここに混ぜない（2026-08-12 著者指摘によるレイヤー純化。テーマ段階に存在するのは「データ」ではなく「一次アクセス」— 自分だけが語れる立ち位置があるか、だけ）
2. **チャンネルは優劣でなく routing**。エッセイを Zenn 実用記事の基準で測らない。逆も然り（Zenn 過剰適合の禁止 — 著者はエッセイ類を Zenn 記事より高く評価している）
3. **過去記事をアンカーにしない**。過去作との pairwise は天井を過去に固定し、過去超えを構造的に禁じる（2026-08-12 著者判断で撤去）。厳しさの供給源は T3 — **現在の外部言説との差分**。世の言説が進むほど基準は自動的に上がる
4. **テーマランクは記事の上限（ceiling）**。改稿ループを回す前に上限を知る。ただし却下ゲートではない — Drop を選べるのは著者だけ（価値観 6 項「取り止めも正当な出口」）
5. **人間の主戦場はここ**。Deepen の問いに答えるのは著者。テーマ評価は著者の思考を深める装置であって、代行ではない。**この評価器の目的は選別ではない** — 「厳しい評価を通じて、著者が持った問いを協同で深め、読者に良い形で届ける」（著者 2026-08-12）。verdict は道具、本体は Deepen の対話。著者の思い入れがある問いに低い verdict が出ても、それは測定エラーではなく正直な判定として扱う（過剰適合の修正は行うが、忖度の再調整は行わない）
6. **fresh context で判定する**。執筆セッションの文脈を持ったまま判定すると甘くなる

## 入力

- テーマ一行（「この記事は◯◯という問い/主張を扱う」に整形してから判定。整形できないこと自体が Deepen シグナル）
- 素材: 所感・X ポスト・会話ログ・証拠台帳（あれば）
- **完成稿を判定する場合**: 記事からテーマ（問い）だけを抽出して判定する。実測数値の量・文章の出来・構成の質は見ない（それは article-judge の領分）

## Step 1 — 共通核 8 問（チャンネル非依存・各 1 行証拠必須）

| # | 質問 |
|---|---|
| T1 | 問い/テーゼが**一文で**言えるか（言えるまで圧縮を試みる） |
| T2 | **非自明性**: 答えは読者の認識を裏返すか（正しければ驚く問いか。既存常識の確認・敷衍なら No） |
| T3 | **言説の空白**: 同型の問い・主張の先行を**外部検索で照合**したか。空白または明確な差分があるか（記憶で断言しない — knowledge-staleness。厳しさの主供給源はここ） |
| T4 | **一次アクセス**: 自分だけがこれを語れる立ち位置・体験・素材が手元にあるか（強度は問わない — 強度の検証は execution 層） |
| T5 | 読者自身の問いに接続するか（著者の身辺雑記で閉じていないか） |
| T6 | Dinner Party Test: 著者の興奮は表層でなく、その裏の原理・深い問いにあるか |
| T7 | 2,000 字級の議論を埋める深さがあり、かつ記事 1 本で問いが閉じるか（ポスト 1 本の火花なら No） |
| T8 | トレンド・ドラマへの寄生でないか（一過性のニュースが消えたら問いも消えるなら No） |

## Step 1.5 — チャンネル routing（優劣ではない）

- **読者が手を動かして再現する問い** → Zenn（実用軸）。適合確認として Z1: 検索する読者が想定できるか / Z2: 数秒で「自分ごと」と分かる形にできるか
- **思索・立場表明・言説への介入** → note エッセイ（→ EN 翻訳して Substack）
- routing は verdict の上下に影響しない。「エッセイだから」「how-to だから」で A/B は動かない

## Step 2 — 反証プレッシャーテスト

- 「A 見込み」への**必須 2 問**: ① この問いへの反例・対抗言説を 1 つ挙げよ — テーマを壊すか、深化の素材か。② **この問いを B（標準的な公開価値どまり）と主張する最強の論を 1 行で作れ** — 反駁できなければ B。**迷ったら B**
- 「Deepen」に対して: 弱いのは問い自体か、問いの**言語化**か（言語化だけなら T1 の圧縮で解決する）

**希少性モニタ**: A は例外であって既定ではない。直近 10 本中 2 本以上に A を出していたら基準ドリフトを疑い、直近の A を反証②で再審する（分布クォータではなく事後の自己点検）。

## Step 3 — named verdict（集計しない・次アクション 1:1）

| verdict | 条件 | 次アクション |
|---|---|---|
| **Write-A見込み** | 共通核 **8/8 Yes**（T3 は検索照合済み）+ 反証②を反駁 | 執筆へ |
| **Write-B見込み** | 共通核は概ね通るが A 条件に欠け | 執筆へ（上限を台帳に記録。A 相当の実測を期待しない） |
| **Deepen** | T1 が言えない / T2・T3 が No / dominant No が致命的 | 深化プロンプトを実行して再判定（同一質問セット） |

dominant No の例: T3 で同型の先行言説が見つかった → 角度を変えない限り A は出ない。

## Deepen — 深化プロンプト（verdict に必ず添える。2 回まで）

2 回で上がらなければ「B/C 見込みのまま記事化」を著者に返す（却下しない）。

1. **反証調査** — 問いと逆方向の言説・データを外部検索で集める。反証は敵ではなく、対立軸を一段上げる素材（例: 「AI で仕事が減る/増える」→「増えた仕事は本物の需要か」）
2. **問いの一段掘り** — なぜそうなるのか / だから何なのか / それは誰の問題か。所感の裏の機序に名前が付くまで
3. **言説の空白の地図化** — 隣接言説（誰が・どこまで言ったか）を並べ、自分の一文がどの空白に立つかを特定する
4. **鮮度照合** — 素材の as-of を確認し、直近 1 ヶ月の変化で前提が動いていないか

### Worked example（2026-08-12 実セッション）

初期テーマ「AI 自動化を進めたら頼むことが枯渇してきた、という所感」→ T1 は言えるが T3 未照合 → **Deepen 1 回目**: 反証調査で「残業増・workslop・偏愛言説」が出る → 対立軸を「増えた仕事・湧いた欲望は本物か」へ上げ、「欲望の枯渇の一人称言語化は日英とも空白」を確認（T3 Yes に転化）→ **Deepen 2 回目**（著者入力）: 成長モデル批判・「お前はどうしたいんだ」への収束 → A 見込みで執筆へ。**反証が問いを 2 段深くした**。
