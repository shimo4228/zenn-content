# Kaguura Craft チェックリスト（完全版・評価関数用）

品質バーの正本。著者の過去記事ではなく本チェックリストを基準アンカーにする（2026-08-12 著者決定）。
各項目は二値質問（Yes/No + 1 行証拠）の形で書く。**判定は集計せず**、llm-as-judge の named verdict へ。

日本語適用の言い換えは各項目の JP: に示す。writing-ecosystem の Craft 規約はこのリストの抜粋 — 齟齬があれば本リストではなく writing-ecosystem 側を著者確認の上で更新する。

## A. 機械層（mechanical_checks.py — 決定論検出、judge の外）

| # | チェック | 検出方法 |
|---|---|---|
| A1 | 集団への呼びかけがないか（Stadium 禁止） | JP: 「皆さん」「みなさん」「読者の皆様」等の照合 |
| A2 | 程度副詞の密度が低いか（Kill Adverbs） | JP: 「とても・非常に・かなり・しっかり・すごく・本当に」等の出現率。閾値超過を報告 |
| A3 | 格式語が平易語に置き換わっているか | JP: 「活用する→使う」「実施する→やる」等のリスト照合（writing-ecosystem 由来） |
| A4 | 段落長のばらつきがあるか（LinkedIn ロボット禁止 + 3 文超過） | 段落ごとの文数分布。全行独立（1 行 1 段落連続）と 3 文以上段落の両方を報告 |
| A5 | 文長のばらつきがあるか（長い蛇行文の検出） | 文字数分布。極端に長い文（目安 100 字超）を列挙 |
| A6 | 分量が密度レンジ内か | 目安 800–2,000 語（JP: 約 2,000–5,000 字）。超過/不足は報告のみ（判定しない — 密度が本体） |
| A7 | AI slop 語・決め構文がないか | writing-ecosystem 禁止リスト + 「〜ではなく〜だ」構文（EN: not-X-but-Y の echo 形のみ）+ em-dash + triad（2026-08-13 再設計: 予告つき列挙「3 つの〜」+ bold 段落のちょうど 3 連のみ。読点数ヒューリスティックは偽陽性過多で廃止） |
| A8 | **voice 回帰**（改稿ラウンド間） | 一人称率・文長分散・平均文長の初稿比変化率。閾値超過 = over-editing 警告（Kaguura 7.2: over-editing はユニークな声を殺す） |
| A9 | タイトルに具体（数字・期間・固有名）が含まれるか | 数字/固有名の有無を報告（無し = LLM 層 B9 で意味判定） |
| A10 | 指示語の指示先候補（judge K4 の証拠） | JP: 「あの」「さっきの」「先ほどの」の出現を行番号付きで列挙（報告のみ — 回収可能かは K4 が判定。2026-08-13 新設） |
| A11 | 読者への語りかけマーカー（judge B6 の証拠） | JP: 「ください」「ませんか」「でしょうか」「ましょう」「あなた」/ EN: you・your の件数を stats に報告（**stats-only、finding にしない** — 発見調 essay は 0 件でも正当。真に迫っているかは B6 が判定。2026-08-20 新設） |

EN 記事（substack/*-en.md 等）は `--lang en` で実行する（EN slop リスト・文分割・800–2,000 語 advisory に切替。ja 既定のまま流すと lang_mismatch が報告される）。

## B. LLM 層（article-judge の固定コア質問 — 二値 + 1 行証拠）

### 構成（Hero's Journey 4 段 — 2.2）

- B1 **Calm Story**: 冒頭は身近で具体的な場面・体験から入っているか（理論・データ・背景説明から入っていないか）
- B2 **Warm-up 削除**: 冒頭 3 段落に「なぜ書いたか」「背景の前置き」の warm-up がないか（読者は行動の最中に投入されているか）
- B3 **Plunge**: 読者が乗った後に、緊張（問題・不都合な真実・パラドックス）が明確に提示されるか
- B4 **Solution**: 緊張に対する枠組み・中核ルールが読者を引き上げる形で提示されるか
- B5 **Higher Ground**: 開始時より高い位置で終わるか。安っぽい N ステップまとめ・エンゲージメント餌（「感想をコメントで」）で終わっていないか。読者を軽くして返しているか

### 文（Writing Etiquette — 1.2）

- B6 **単数の読者**: 全体が一人の読者への手紙として読めるか。集団呼びかけの不在（A1）だけでは Yes にしない — **掴みまたは結論に、読者の具体的状況を名指して直接語りかける文（問い・指示・読者主語の約束）があり、それが「自分のことを言われている」と感じる精度か**。誰にでも当てはまる一般論の問いかけは語りかけと数えない。A11 の件数は証拠（0 件 = 中立解説文を疑う。ただし発見調 essay の問い化は語りかけを兼ねる）（2026-08-20 積極形を追加 — 正本: writing-ecosystem「語りかけの積極形」）
- B7 **能動態**: 主語が動く文が既定か（行為者を伏せる意図のない受動文が残っていないか）
- B8 **具体イメージ**: 抽象概念が絵になる具体（「日給 10 ドルで土を掘る」型）に置き換えられているか
- B9 **密度**: 各文は論点を前に進めているか。中盤の反復・埋め草はないか（10% ルール: 削れる文を 3 つ挙げられるなら Fix）

### タイトル（3.6 / 6.4.1）

- B10 タイトルは topic 型でなく outcome 型か（「〜の分析」「〜についての考察」は宿題に見える）
- B11 詩的曖昧タイトルでないか（フィード上で 5 秒で内容が分かるか）
- B12 賢い友人からのテキストのように読めるか（SEO ロボット調でないか）

### 人間性・声（4.4 House Guest Rule / 6.5）

- B13 一人称の実体験・場面が論点に奉仕する形で入っているか（venting でも TMI でもなく、証人として）
- B14 企業メモ調・過剰に消毒された言い回しになっていないか
- B15 主張は言い切られているか（安全な両論併記に逃げて「誰も言わなかった本音」を言い損ねていないか — Conviction）

### 判定注意（6.5.2 の教訓）

- ストーリーテリングと発想の質は書式の瑕疵を上回りうる。**A 層の違反件数だけで verdict を決めない**（機械層は証拠であって判定でない）
- 判定に迷ったら「この記事は読者の時間を尊重しているか（density over word count）」を dominant question にする

## C. テーマ層（theme-eval へ — 記事の上限を決める側）

- C1 **隠れた不満の言語化**: 多くの人が感じているのにまだ言葉にされていないことに言葉を与えているか（6.5: "puts words to a hidden frustration"）
- C2 **Dinner Party Test**: 著者が友人に興奮して話すのは技術的な表層でなく、その裏の原理・深い問いか。このテーマはそれに当たるか（4.3）
- C3 **検証済みの火花**: テーマは反応の実測（X 所感への反応・会話での手応え）から来ているか、机上の発明か（3.2 Validation Loop — 著者の X ポストは Notes に相当）
- C4 **一過性でないか**: トレンド・ドラマ追いでないか（7.1: Algorithm Chasing は声を毀損する）
- C5 **密度の見込み**: このテーマは 2,000 字級の議論を埋める深さがあるか、Note（ポスト）1 本で終わる火花か

## D. ループ設計への制約（このリスト自身が課すもの）

- **over-editing 禁止**（7.2 Perfectionism Trap）: 「fluff を削って出す」以上の磨き込みは声を殺す。改稿ループ上限 2 ラウンド・A8 voice 回帰の根拠
- **テンプレの機械的充填禁止**（3.3 警告）: 4 段構成やチェック項目を「埋める」ための加筆を Fix 指摘として出さない。実内容が既にあるものの配置換え・削除を優先する
