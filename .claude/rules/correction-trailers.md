# 著者の指摘を commit に残す（試行 2026-09-28〜10-12）

著者の指摘が記事を変えたら、その指摘を著者の言葉のまま commit 本文に残す。別の台帳は作らず、commit を一次記録にする。

## 積む（指摘を受けたその場で）

著者の発言が brief・構成・本文・タイトルのどれかを変えたら、反映と同じターンで `drafts/<slug>.corrections.md`（gitignore 下、非公開）に 1 件ずつ追記する。

```markdown
## C<n>
- 原文: 「<著者の発言をそのままコピー。要約・言い換えをしない>」
- 対象: <brief / 節名 / 文>
- 修正前: <抜粋 2 行まで>
- 修正後: <抜粋 2 行まで>
- Trigger: <何が起きて著者が指摘したか（例: 通読で結論が 2 つに読めた）>
- Expect: <この修正が外れていたと分かる観測（例: 公開後の反応で同じ箇所が誤読される）>
```

- 積むのは著者の指摘だけ。reviewer や機械の指摘は writing-ecosystem の処分記録が持つ
- 1 つの発言が複数箇所を変えたら、原文は 1 回、対象を並べる
- 著者が反映を却下・撤回したら、その件に「撤回」と書いて残す（消さない）

## 写す（その変更を含む commit で）

記事の commit 本文に、積んだ件を 1 件 1 ブロックで写す。既存の `Context:` / `Decision:` / `Review-when:` の後ろに置く。

```text
指摘: 「<原文>」
Trigger: <…>
Expect: <…>
```

- 写す前に「Public-repository safety」（CLAUDE.md）を原文にも当てる。個人のパス・秘密・第三者の非公開情報は `[略]` に置き換え、置き換えたことを同じ行に書く
- 修正前の稿そのものは commit しない。前後の抜粋は `drafts/` に残る
- 写し終えた件には `drafts/` 側に commit の SHA を書き足す

## 試行の読み（2026-10-12）

- 数える: 著者起点の変更のうち原文付きで commit に残った割合 / 原文が会話と一致した割合（その期間の session ログと照合）/ 著者の手間の体感
- 撤退: 原文付きが半分未満、または原文が会話と食い違う件が出た
- 結果は harness RFC-0028 の Status に書く。続けるなら writing-ecosystem の処分規律へ移し、この rule は消す
