# AI の文章は、なぜ宙に浮いて感じるのか

AI が書いた文章を読んでいて、ときどき妙な感じがします。人間と前提を共有していない感じです。一文ずつは正しくて読みやすいのに、全体が空疎で、宙に浮いている。野球でいえば、ストライクゾーンが違う。こちらが構えているところに球が来ず、振っても、まるで違う競技をしているような感覚になります。

たとえば、毎朝読んでいる研究レポートです。私は AI エージェントの設計について答えを探している問いをいくつか持っていて、自作のパイプラインがその問いに関係する論文を毎日集め、LLM が数段落の日本語の説明にまとめます。ある朝のレポートには、こう書かれていました。

> 一つ目の研究が扱った問題は、指示だけでは行動のずれを捉えにくいことだ。

> 二つ目の研究が扱った問題は、周辺機構（harness）の自己改変が、練習課題を覚え込むおそれだ。

すらすら読めます。でも、どの論文の話なのかが最後まで分かりませんでした。論文を読んでいない私にとって、「一つ目の研究」は何も指していません。

この感じはどこから来るのか。この一週間ほど、AI と文章を書くなかで同じ感じに何度もぶつかったので、その場面を並べて考えてみます。

## ずれには二つの向きがあった

一つ目は、読み手がすでに知っていることを説明してしまう向きです。Claude Code と一緒に、エンジニア向けの技術記事を書いていたときのことです。下書きは、スキルを「エージェント自身の経験から作った50余りの短い手順書（skill）」と説明していました。私は「読者はスキルくらい知ってる。説明がいらない」と返しています。

二つ目は、読み手に要るものを飛ばす向きです。別の記事の下書きには「朝の記事の末尾に、私は…と書きました」という一文がありました。「朝の記事」は、その日の朝に私が公開した別の記事のことです。Claude Code と私は同じ日の作業の中にいるので、それで通じます。読者には通じません。私は「私が同日の午後にこの記事を書いていることなど読者は知る由はないのだから、きちんとどの記事のどの部分なのか明示しないとなにもわからない」と書き返しました。冒頭のレポートも、こちらの向きです。論文を読んでいない読者にこそ要る論文の名前が、抜けていました。

厄介なのは、どちらの向きも、規則を守った結果として起きていたことです。冒頭のレポートを書く LLM に渡すプロンプトは、読者を「今日の論文は読んでいないし、その分野の専門用語も知らない」人と想定し、「専門用語を使わずに」書くよう求めていました。LLM はそのとおりに書き、論文の名前まで外しました。本番に入れる前に試した稿は、書いた説明が元の論文に忠実かどうかを別の LLM に判定させる検査（LLM-as-a-judge）も通っていました。

この記事の下書きも同じでした。この記事の下書きも Claude Code が書いていて、Claude Code には媒体ごとの読者を定めた執筆の規約を読ませています。note の読者は「AIを仕事や生活で使う一般読者」と書いてありました。それを見て技術の言葉は避けようと考えた Claude Code は、プロンプトを「指示文」と言い換え、Codex のサブスクリプションで動く GPT-5.6 Sol を「定額の契約の範囲で動かせる別の会社のモデル」と書きました。読み手が知っている言葉を知らないものとして扱う、一つ目の向きです。前提を補う一文も、あちこちで抜けていました。こちらは二つ目の向きです。通読した私の言葉です。「指示文ってなに？」「絶妙に前提を外すから宙に浮いている」「伝聞できいたことから場面を再現しているような文章になっている」。

## 前提は、確かめながら積むもの

この感じに近い概念が、言語学にありました。心理言語学者の Herbert Clark と Susan Brennan は、会話する二人が共有している知識・信念・想定を「共通基盤（common ground）」と呼びました（1991年）。二人はこの共通基盤を一瞬ごとに更新しなければならず、話したことが相手に理解されたかを確かめながら更新していく過程を、grounding と呼んでいます。「車を持ってる？」と聞いて「車？」と聞き返されたとき、話し手は初めて、相手がまだ分かっていないと知ります。会話の前提は、こういう小さな確かめの積み重ねでできています。

LLM については、Omar Shaikh らが 2024年の論文でこの点を調べています。対話の中で LLM が生成する文章は、人間に比べて確かめの行為（聞き返しや、了解の表明）が少なく、「共通基盤があると決めてかかった」文章になっていた、という報告です。調べられたのは対話で、記事やレポートではありません。それでも、私の感じていた違和感は、この「決めてかかった」にかなり近いと思います。

これらの場面を見直すと、AI の書き手の手元にあったものがはっきりします。読み手その人はいません。あるのは、文字で書かれた読者の説明です。「今日の論文は読んでいないし、その分野の専門用語も知らない」。「AIを仕事や生活で使う一般読者」。そして、出来事そのものではなく、会話ログや作業の履歴から抜き出した記録です。AI はこの説明と記録から、読み手が何を知っているかを推定し、それを共有済みとして書きます。推定がずれれば、知っていることを説明し、要る前提を飛ばします。場面を経験していないので、記録に書かれていない当たり前の前提は、文章にも書かれません。私が「伝聞」と感じたのは、たぶんこれです。

ストライクゾーンのたとえに戻ると、AI はキャッチャーのミットを見ずに、ゾーンの説明書きを読んで投げています。

## ずれを直したのは、止まった読み手だった

では、先回りして規則を足せば直るのか。私の経験では、直りませんでした。この執筆の規約には、前の記事を書いたときに「既存の用語は言い換えずに使い、初出で説明する」という規則を足してありました。それでも、この記事の下書きは「指示文」と書いています。調べると、同じ規約の上のほうに、以前から「日常語で言えるなら専門用語を使わない」という行があり、足した規則と正面からぶつかっていました。Claude Code は、規則を破ったのではなく、上にある規則を守って「指示文」と書いたのです。

ずれが直ったのは、実物の読み手が止まって、どこで止まったかを言ったときでした。いちばん大きく直ったのは、この記事そのものです。

この記事は最初、「AI の文章から論文の名前が消える」という話として書かれていました。Claude Code が下書きを何度直しても、私の通読は「ちょっと全体的に何が言いたいのかわからない。冗長すぎる」で止まりました。そこで私は、自分が何に引っかかっているのかを言葉にしました。「ちょっとAIの文章に感じる違和感をいうと、人間と前提を共有していないと感じる。何か空疎で宙に浮いているような感じだ」。記事の問いは、この一言で入れ替わりました。冒頭の段落は、このとき私が言ったことを書き起こしたものです。

Clark の言葉でいえば、私の通読と、止まったところで言ったこの一言が、書き手に欠けていた grounding の役を担っていたことになります。

では、ここからどう変えるか。この結論にたどり着く前、Claude Code は、書く前に読者の前提の一覧を作らせる、といった手順を足す案を出しました。私は「それも外科処置ではないか」と返しています。手順を足すのも、読者についての説明書きをもう一枚増やすことだからです。

だから私は、記事の問いは、AI に推定させずに自分の言葉で言うことにしました。この記事でいちばん強い箇所は、冒頭の違和感の段落と、問いを入れ替えた一言です。どちらも、Claude Code が推定して書いた文ではなく、私が通読の途中で口にした言葉がそのまま入ったところでした。

会議の要約でも、調べものの報告でも、AI の文章が宙に浮いて感じるとき、問うべきは、上手く書けているかではないのだと思います。この文章は、私が何をすでに持っていると決めてかかっているか。そして、止まったところを書き手に返すこと。私とこの書き手との間で実際に効いた確かめは、それでした。

AI の書き手が、自分から「ここは分かりますか」と確かめられるようになるのかは、まだ分かりません。
